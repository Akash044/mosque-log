# Mosque Finance Tracker

A Flutter + Firebase Android app for tracking a mosque's income (general
donations, Jumma collections, monthly contributions, Eid collections) and
expenses, with Bangla/English localization and light/dark themes.

## Features

- **Email/Password + Google sign-in** via Firebase Authentication
- **Dashboard** — live totals: total income, total expense, this week's income,
  Jumma income, net balance
- **Income** — four tabs:
  - General donation (donor name, amount, optional quantity, date)
  - Jumma collection (Friday-only date picker + amount)
  - Monthly collection (person + multi-month chips, hides already-paid months
    for the selected person, with searchable person dropdown)
  - Eid collection (Eid al-Fitr / Eid al-Adha + amount + date)
  - History list below each form with swipe-to-delete
  - Filter monthly history by person / month / year
- **Expense** — scrollable month tabs + year navigator, swipe-to-delete,
  built-in calculator dialog (+ − × ÷) for the amount field
- **Report** — date-range picker, income breakdown by type, expense by
  category, net balance for the range
- **People management** — list, toggle active/inactive, delete, add new
  (phone number required)
- **Bangla / English** with Bangla numerals (০–৯) and localized month names
  in Bangla mode
- **Light / Dark / System** theme

## Tech stack

| Concern | Choice |
|---|---|
| Framework | Flutter 3.41 (Dart 3.11) |
| Auth | `firebase_auth` + `google_sign_in` |
| Database | `cloud_firestore` (single-mosque, shared documents) |
| State | Riverpod (`flutter_riverpod`) |
| Routing | `go_router` with auth-state redirect |
| Localization | `flutter_localizations` + `intl` (ARB files) |

## Firestore data model

Top-level, single mosque (no `mosques/{id}` scope yet):

```
persons/{personId}
  name, phone, active, createdAt

income/{incomeId}
  type:       "general" | "jumma" | "monthly" | "eid"
  amount:     number
  quantity:   number | null         (general only)
  donorName:  string | null         (general only)
  date:       Timestamp
  personId:   string | null         (monthly only)
  months:     ["2026-01", ...]      (monthly only — array of YYYY-MM)
  eidType:    "Eid al-Fitr" | "Eid al-Adha" | null
  createdBy:  uid
  createdAt:  Timestamp

expenses/{expenseId}
  expenseType, amount, date, createdBy, createdAt
```

Storing `months` as a `YYYY-MM` string array lets the "who hasn't paid this
month" query use `arrayContains` without a composite index.

### Security rules

`firestore.rules` requires `request.auth != null`:

```
match /{document=**} {
  allow read, write: if request.auth != null;
}
```

Tighten by adding an `admins/{uid}` collection and checking membership if
you want only approved accounts to write.

## Prerequisites

- Flutter 3.41+ (Dart 3.11+)
- JDK 17 (Microsoft OpenJDK works)
- Android SDK + platform 36 + build-tools 36 (Flutter 3.41 requires SDK 36)
- A Firebase project with Email/Password + Google sign-in enabled and
  Firestore created in a region close to your users (e.g. `asia-south1` for
  Bangladesh)
- Android Studio or a physical Android device with USB debugging on

## Setup

1. Clone the repo:
   ```powershell
   git clone <your-repo-url>
   cd mosque-expense-tracker
   ```
2. Fetch packages:
   ```powershell
   flutter pub get
   ```
3. Connect your Firebase project (this generates `lib/firebase_options.dart`
   and downloads `android/app/google-services.json`, both per-environment):
   ```powershell
   dart pub global activate flutterfire_cli
   firebase login
   flutterfire configure
   ```
   Pick your project, select `android` only, accept the default app id.
4. Add **both** debug **and** release SHA-1 + SHA-256 fingerprints to your
   Firebase project (Project Settings → Your Android app → Add fingerprint).
   Google Sign-In silently fails without them. Get the debug SHA-1 with:
   ```powershell
   cd android
   ./gradlew signingReport
   ```
5. Deploy the Firestore rules:
   ```powershell
   firebase deploy --only firestore:rules
   ```
6. Run the app:
   ```powershell
   flutter devices    # confirm your phone is listed
   flutter run -d <device-id>
   ```

## Known gotchas on Windows

- **Project on a different drive from the Pub cache.** Kotlin's incremental
  compiler can't relativize paths across Windows drive roots. If the project
  is on `E:\` and the Pub cache is on `C:\`, builds fail with
  *"Could not close incremental caches…"*. Fix: keep
  `kotlin.incremental=false` in [android/gradle.properties](android/gradle.properties).
  Moving the project to the same drive as the Pub cache lets you re-enable it.
- **MIUI (Xiaomi/Redmi) blocks USB installs by default.** Enable **Settings →
  Additional settings → Developer options → Install via USB** before
  `flutter run` — otherwise `adb install` returns
  `INSTALL_FAILED_USER_RESTRICTED`.
- **"Dubious ownership" git warning** on E:\ drives. Run once:
  ```powershell
  git config --global --add safe.directory "E:/Mosque Expense Tracker"
  ```

## Localization

Strings live in [lib/l10n/app_en.arb](lib/l10n/app_en.arb) and
[lib/l10n/app_bn.arb](lib/l10n/app_bn.arb). After editing, `flutter pub get`
(or `flutter gen-l10n`) regenerates `lib/l10n/app_localizations.dart`
(gitignored — it's a build artifact).

When in Bangla mode, `intl`'s number/date formatters produce Bangla numerals
(০–৯) and localized month names automatically. Stored values in Firestore
remain plain numbers/timestamps — formatting is display-only.

## Build a release APK

1. Generate a release keystore (one-time, keep it safe):
   ```powershell
   keytool -genkey -v -keystore release.jks -alias upload -keyalg RSA -keysize 2048 -validity 10000
   ```
2. Create `android/key.properties` (gitignored) with the keystore details.
3. Wire it into `android/app/build.gradle.kts` per the
   [Flutter signing docs](https://docs.flutter.dev/deployment/android#signing-the-app).
4. Add the release keystore's SHA-1 + SHA-256 to Firebase, then:
   ```powershell
   flutter build apk --release
   ```
